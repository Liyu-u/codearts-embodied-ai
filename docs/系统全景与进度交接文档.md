# 具身智能闭环系统全景与进度交接文档

> 文档用途：团队进度同步、新成员接手、联调排障、比赛材料准备。
> 核对基线：2026-08-22，`main@beae136`。
> 项目赛题：2026 年度中国青年科技创新“揭榜挂帅”擂台赛，华为题目 `XH-202618`——“基于华为云码道 CodeArts 代码智能体解决复杂软件工程问题”。

## 1. 先看结论

本项目已经形成一条可运行、可观察、可阻断、可有限修复的具身智能软件闭环：

```text
环境/场景
  ↓ perception.v1
A：自然语言意图理解
  ↓ task.v1
B：CodeArts 策略生成
  ↓ strategy.v1
C：Mock / Isaac Sim 执行
  ↓ execution.v1
D：TraceCoder 反馈、诊断与有限修复
  ↓ feedback.v1；必要时回到 C，最多重试 2 次
```

截至当前，系统已经达到“比赛演示级原型”的完整度：A、B、D 均有真实智能模型或智能体调用路径；B 已接入华为云 CodeArts CLI；C 已在远程 Isaac Sim 6.0 CUDA 环境中完成 Ground Truth 感知和真实物理执行；本地还提供可视化 Demo、Mock 回归、契约测试和量化基准。

但项目还不能表述为“生产完成”或“全部验收完成”，主要原因有五点：

1. 真实视觉感知和真机执行尚未完成，当前远程感知来自 Isaac Sim 的 USD/PhysX 真值，不是 RGB/RGB-D 相机识别。
2. 最新 7 类 CodeArts 动作扩展提交晚于现有批量报告，需要在当前 HEAD 上补跑一轮正式在线报告。
3. 全量测试受本机 `.env`、`codearts.env` 影响，存在慢调用、挂起或与测试假设冲突的问题，尚未形成隔离配置下的全绿 CI 门禁。
4. 历史“全智能 30 题”报告通过率不高，说明单点真实调用成功尚未转化为稳定的全题集在线闭环。
5. 比赛最终交付物中的 PPT、演示视频/可访问演示环境、许可证与原创性说明、最终测试报告和提交压缩包仍需集中制作。

按当前证据做保守估算：

- 比赛演示原型完成度约为 **75%–80%**；
- 最终参赛材料就绪度约为 **60%–65%**；
- 真实相机、真机和生产稳定性口径仍低于 **50%**。

以上百分比是交付管理估算，不是自动化质量分数；后续应以本文件第 9 节的退出条件判断是否真正完成。

## 2. 系统解决什么问题

传统机械臂 Demo 往往把“语言解析、动作规划、执行控制、结果判断”写在一个脚本里，演示可以运行，但难以回答以下问题：

- 模型到底理解了什么，绑定了哪个物体？
- 策略是本地规则生成，还是 CodeArts 真实生成？
- 模型生成的内容是否经过安全校验？
- 仿真执行失败后，系统为何重试或停止？
- 每个模块如何独立替换、测试和追责？

本项目的核心价值不是单纯“让机械臂搬一次方块”，而是把复杂的软件工程链路拆成明确模块，用五类版本化 JSON 契约连接，并为外部模型输出建立本地确定性安全门。它强调：

- **可复现**：离线 Mock 与基准题集可重复运行；
- **可审计**：任务 ID、模型、provider、request ID、延迟、回退和验证结果可追踪；
- **可替换**：A/B/C/D 通过适配器和 Schema 解耦；
- **安全优先**：歧义、未知实体、非法动作、越界、碰撞和修复越权均应阻断；
- **真实 CodeArts 参与**：B 通过官方 CLI 生成结构化策略，不把 CodeArts 冒充为普通聊天模型接口。

## 3. 架构、数据流与职责边界

### 3.1 五类接口契约

`contracts/v1/` 是跨模块接口的唯一标准。

| 契约 | 生产者 | 消费者 | 关键内容 |
| --- | --- | --- | --- |
| `perception.v1` | P/C 感知层 | A、C | 场景、稳定对象 ID、位姿、属性、执行能力和空间关系 |
| `task.v1` | A | B、D | 动作、目标 ID、目的地 ID、约束、READY/澄清/阻断状态 |
| `strategy.v1` | B 或 D 补丁 | C | 白名单原子步骤、引用、恢复策略；`code` 必须为空 |
| `execution.v1` | C | D、前端、报告 | 步骤状态、轨迹、耗时、安全事件、执行后端来源 |
| `feedback.v1` | D | Pipeline、前端 | 诊断、是否可重试、受限补丁、模型与校验证据 |

所有外部智能输出都被视为不可信输入。进入下一模块前，至少要经过 Schema、动作白名单、参数、稳定 ID、引用和安全能力校验。

### 3.2 正常流程

1. 感知模块产生 `perception.v1`。
2. A 将自然语言与场景事实编译成 `task.v1`。
3. 若 A 返回 `NEEDS_CLARIFICATION` 或 `BLOCKED`，Pipeline 立即停止。
4. B 依据 `task.v1` 和 C 的能力表生成 `strategy.v1`。
5. 若 CodeArts 不可用、输出非法或动作不受支持，`required` 模式下直接阻断。
6. C 只解释白名单原子动作，执行后返回 `execution.v1`。
7. D 消费任务、策略、感知与执行证据，输出 `feedback.v1`。
8. 只有执行失败、D 明确判定可重试、补丁校验通过且未超过上限时，Pipeline 才会重新调用 C。

### 3.3 失败与安全停止

当前安全策略包含以下边界：

- C 仅允许 `detect_object`、`move_to_object`、`grasp`、`move_to_target`、`release`；
- `strategy.code` 必须是 `null` 或空字符串，C 不执行任意 Python；
- 主步骤、恢复步骤、恢复次数和总动作调用均有限制；
- Pipeline 的 D→C 重试最多 2 次；
- C 内部恢复耗尽、碰撞、越界、驱动异常或超时可进入 `SAFE_STOP`；
- `SAFE_STOP` 后 Pipeline 不再接受 D 的继续执行建议；
- D 的补丁必须再次通过与 B/C 共用的 `integration/strategy_policy.py` 语义门。

### 4.2 P/C 感知模块

关键路径：

- `modules/perception/mock_scene.py`：本地确定性场景；
- `modules/perception/observation_normalizer.py`：正式观察消息归一化；
- `modules/perception/isaac_ground_truth.py`：读取实时 USD/PhysX 位姿并生成 `perception.v1`；
- `integration/adapters/perception.py`：Mock/观察消息统一边界；
- `integration/adapters/isaac_perception.py`：Isaac Ground Truth 适配器。

当前 Ground Truth 模式由“语义 manifest + 仿真实时位姿”组成。它适合证明 A/B/C/D 的接口和物理闭环，但不能被称为“视觉识别”。下一阶段应加入相机图像、深度/点云和检测置信度，并继续用 Ground Truth 做仿真对照。

### 4.3 A：意图理解

关键路径：

- `modules/intent_understanding/adapter.py`：唯一跨模块适配入口；
- `robot_intent_agent/semantic_parser/`、`semantic_reasoner/`：语义解析与融合；
- `grounding/`：从场景中绑定稳定实体 ID；
- `constraint/`、`safety/`：约束与安全门；
- `ir/`、`schemas/`：内部 IR 和 `task.v1` 投影。

运行模式：

- `rule`：离线、确定性，适合基础回归；
- `llm`：强制模型语义路径，正式智能验收使用；
- `hybrid`：规则事实与模型候选融合。

当前应重点关注规则模式与 LLM 模式的语义一致性。最新实跑中，部分安全门单测在规则模式下不能得到预期的 `TARGET_NOT_GRASPABLE` / `DESTINATION_VALIDITY_UNKNOWN` 原因，而本机 LLM 配置下通过，说明测试尚未完全隔离，两个引擎的动作枚举映射也需要统一。

### 4.4 B：CodeArts 策略生成

关键路径：

- `integration/adapters/strategy.py`：正式 B 适配器；
- `modules/strategy_generation/codearts_agent.py`：CodeArts CLI 调用、结果解析和动作级校验；
- `modules/strategy_generation/codearts_system_prompt.md`：智能体提示词；
- `integration/strategy_policy.py`：B/C/D 共用安全语义门。

当前共同开放的用户级动作是：

- `pick`、`grasp`：生成检测、接近、抓取三步；
- `pick_and_place`、`place`、`transfer`、有明确目标区的 `fetch`：生成五步抓取搬运；
- `stack`：五步流程，`move_to_target` 必须带 `placement_mode=stack_on`。

`push`、`dynamic_grasp`、`handover`、`pour`、`wait`、`custom` 当前仍应在 A/B 边界澄清或阻断。

CodeArts 模式：

| 模式 | 行为 | 建议用途 |
| --- | --- | --- |
| `off` | 完全关闭 CodeArts，使用本地确定性策略 | CI、离线开发 |
| `auto` | 优先 CodeArts，失败后记录原因并安全回退 | 日常联调 |
| `required` | CodeArts 失败或输出非法即阻断，不回退 | 比赛演示、正式证据 |

调用策略：

| 策略 | CodeArts 调用 | 用途 |
| --- | ---: | --- |
| `planner` | 1 次规划 | 低延迟开发与冒烟 |
| `quality` | 规划 + 1 次 critic | 正式演示推荐 |
| `max` | 规划 + 2 次 critic | 发布抽样与高风险验收 |

README 记录 7 类开放动作已完成 7/7 真实 CLI 验证；但该说明与代码位于 20:25 的最新提交，现有最新批量 CodeArts 报告生成于 15:25，因此还应补一份当前 HEAD 的原始在线报告，至少记录每类动作的 request ID、模型、耗时、契约结果、critic 结果和是否回退。

### 4.5 C：执行器

关键路径：

- `modules/executor/strategy_interpreter.py`：解释步骤、引用、恢复和安全停止；
- `modules/executor/mock_backend.py`：本地 Mock；
- `modules/executor/isaac_backend.py`、`isaac_driver.py`：Isaac Sim；
- `modules/executor/real_backend.py`：真机接口和人工确认；
- `modules/executor/safety.py`：工作空间、速度、力、超时、碰撞和急停；
- `integration/config/profiles/*.toml`：local/sim/real 三档配置。

远程 Isaac 证据表明，系统不是简单改写 Mock 位姿：C 经官方 Franka 控制器执行，物体前后位姿从仿真 prim 回读，包含关节轨迹和释放后位姿验证。

当前有一个必须优先修复的安全配置问题：`integration/config/loader.py` 会将 `RIA_DEPLOYMENT_DOMAIN` 对应的全局速度覆盖应用到所有 profile。本机 `.env` 使用 daily 速度 0.30 m/s 时，`real` profile 原本的 0.05 m/s 也会被覆盖到 0.30 m/s，导致相关安全单测失败。真机联调前必须改成“profile 级只收紧、不放宽”，并为 real profile 增加不可提升上限的测试。

### 4.6 D：TraceCoder

关键路径：

- `integration/adapters/tracecoder.py`：`execution.v1` 到 `feedback.v1` 的正式边界；
- `modules/evaluator/tracecoder/`：静态检查、确定性仿真、评分、经验、模型 provider 与修复器；
- `integration/pipeline.py`：受限 patch 的二次验证和重试控制。

D 当前可执行三类决策：

- 执行成功：输出 `D_ACCEPTED`，不重试；
- 可修复失败：生成受限完整策略 patch，验证通过后回到 C；
- 安全事件、不可恢复失败或模型 required 失败：拒绝继续执行。

报告中必须区分：

- C 在一次执行内部依据 B 的 `on_failure` 做动作级恢复；
- D 根据 `execution.v1` 生成 patch 后触发新的 C 执行。

两者不能都统计为“TraceCoder 修复成功”。

### 4.7 Demo 与前端

`demo/` 提供标准库 HTTP 服务和静态前端，不需要 Node.js 构建。它能展示：

- 正常抓取、放置、搬运、取物和堆叠；
- 目标歧义、目标不存在、缺目的地和不支持动作；
- C 内部恢复、持续失败安全停止；
- D 生成 patch 后重试成功；
- 每一层协议、来源、耗时、轨迹和安全事件。

默认 Demo 使用本地 Mock C，并关闭 CodeArts 以保证离线可复现。它适合讲解系统，而不是远程 Isaac 或真机控制台。

## 7. 环境配置与运行方法

### 7.1 基础环境

- Windows 10/11 + PowerShell；
- Python 3.11+；
- Git；
- 真实 B 需要已安装并授权的 CodeArts CLI；
- 真实 A/D 需要 DeepSeek 兼容 API Key；
- 远程 C 需要 VPN、SSH、Docker、NVIDIA GPU、Isaac Sim 6.0 镜像和资产。

Python 依赖较轻：Pydantic、pydantic-settings、python-dotenv 和 OpenAI Python SDK。Isaac Sim 相关依赖位于远程镜像，不通过根目录 `pip` 安装。

### 7.2 首次配置

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup.ps1
```

脚本会创建 `.venv`、安装依赖、生成三个被 Git 忽略的本地配置，并运行体检。脚本不会修改跟踪文件。

严格智能模式：

```powershell
.\tools\setup.ps1 `
  -IntentMode llm `
  -TraceCoderMode required `
  -CodeArtsMode required

.\.venv\Scripts\python.exe tools\doctor_config.py --live-codearts
```

完全离线或 CI 模式：

```powershell
$env:RIA_PLANNER_ENGINE = 'rule'
$env:CODEARTS_STRATEGY_MODE = 'off'
$env:TRACECODER_LLM_MODE = 'off'
```

建议 CI 在不含 `.env`、`codearts.env`、`tracecoder_llm.env` 的干净 checkout 中运行；不要依赖开发者电脑的用户环境。

### 7.3 三个私有配置文件

| 文件 | 模块 | 关键字段 | 是否提交 |
| --- | --- | --- | --- |
| `.env` | A 与通用 RIA 安全配置 | DeepSeek Key、模型、planner engine、速度/力 | 否 |
| `codearts.env` | B | CLI、AK/SK、模式、模型、agent、超时、策略 | 否 |
| `tracecoder_llm.env` | D | DeepSeek Key、模型、模式、超时、最大修复次数 | 否 |

模板分别是 `.env.example`、`codearts.env.example`、`tracecoder_llm.env.example`。

禁止提交 AK/SK、API Key、VPN/SSH 密码、个人 CSV、Cookie 和本机绝对路径。CodeArts AK/SK 也可保存到 Windows 用户环境，但设置后需重新打开终端。

### 7.4 local / sim / real profile

| profile | backend | 用途 | 默认安全特征 |
| --- | --- | --- | --- |
| `local` | `mock` | 日常开发、Demo、CI | 宽工作空间，无人工确认 |
| `sim` | `isaac` | 远程 Isaac Sim | 有限超时、碰撞 fail-closed、CUDA |
| `real` | `real` | 真机小范围验证 | 强制人工确认、窄工作空间、默认 0.05 m/s |

在修复全局环境覆盖问题之前，真机运行前必须打印并人工复核最终 `real` profile，确认速度、力和工作空间没有被放宽。

### 7.5 启动本地 Demo

```powershell
powershell -ExecutionPolicy Bypass -File demo\start_demo.ps1 -Port 8766
```

浏览器访问 `http://127.0.0.1:8766/`。

使用真实 CodeArts B，但仍使用本地 Mock C：

```powershell
powershell -ExecutionPolicy Bypass -File demo\start_demo.ps1 `
  -Port 8766 `
  -CodeArtsMode required `
  -CodeArtsPolicy quality `
  -CodeArtsModel huaweicloud-maas/openpangu-2.0-flash
```

正式展示至少演示：正常成功、A 阶段澄清/阻断、D patch 重试成功、C `SAFE_STOP`、不支持动作阻断。

### 7.6 远程 Isaac 验收

当前推荐入口：

```powershell
.\tools\run_remote_ground_truth_acceptance_final.ps1 `
  -Server <服务器地址> `
  -Port <SSH端口> `
  -User <账号> `
  -StrategyFile <已校验的strategy文件> `
  -Device cuda
```

脚本会检查 SSH/Docker/GPU、上传最小代码包和脱敏策略、启动无网络 Isaac 容器、等待 `perception.json`/`execution.json`、下载证据并检查 `SUCCEEDED`。

当前脚本中仍有校内服务器、账号、资产路径和镜像的默认值。对外发布前应全部改成参数或部署模板，并确认仓库历史和报告不含凭证。

## 8. 测试、验收与报告方法

### 8.1 测试分层

建议按由快到慢的顺序运行：

```powershell
# 1. 契约 JSON 语法
make contract-test

# 2. 契约测试
.\.venv\Scripts\python.exe -m unittest discover -s tests\contract -t . -v

# 3. 单元测试
.\.venv\Scripts\python.exe -m unittest discover -s tests\unit -t . -v

# 4. 集成测试
.\.venv\Scripts\python.exe -m unittest discover -s tests\integration -t . -v

# 5. 18 道闭环验收
.\.venv\Scripts\python.exe -m unittest tests.e2e.test_closed_loop_acceptance -v

# 6. Demo 质量与 HTTP
.\.venv\Scripts\python.exe -m unittest `
  tests.e2e.test_demo_scenarios `
  tests.e2e.test_demo_quality `
  tests.e2e.test_demo_http -v
```

在当前问题修复前，不建议直接把 `python -m unittest discover -s tests -t .` 当作唯一入口，因为它可能读取本机智能配置并进入慢路径。

### 8.2 确定性基准

```powershell
.\.venv\Scripts\python.exe tools\run_closed_loop_benchmark.py `
  --mode baseline `
  --repeats 3 `
  --output reports\closed_loop_benchmark_baseline_repeat3.json
```

关注：

- `pass_rate`；
- `case_stability_rate`；
- `strategy_contract_pass_rate`；
- `repair_success_rate`；
- `safe_stop_correct_rate`。

### 8.3 CodeArts 专项

先运行离线格式与故障注入题集，再做单题在线冒烟，最后分批扩大。

```powershell
# 离线专项
.\.venv\Scripts\python.exe tools\run_codearts_testsets.py `
  --set normal_scale_functional `
  --set normal_scale_semantic `
  --set normal_scale_safety `
  --set normal_scale_resilience `
  --set normal_scale_stability `
  --repeats 2 `
  --output reports\codearts_testsets_normal_scale.json

# 在线单题冒烟
.\.venv\Scripts\python.exe tools\run_codearts_testsets.py `
  --set normal_quality `
  --live `
  --policy quality `
  --limit 1 `
  --pure `
  --model huaweicloud-maas/openpangu-2.0-flash `
  --timeout-s 180 `
  --output reports\codearts_testset_normal_live.json
```

在线报告至少满足：

- `all_passed=true`；
- `all_stable=true`；
- `contract_failures=0`；
- `provider_calls` 等于预期在线成功样本数；
- `fallback_count=0`（required 模式）；
- critic 次数与 `quality/max` 策略一致。

真实 CodeArts 任务不要并发运行。当前观测时延约十几到三十秒，并发会污染稳定性结论。

### 8.4 正式全链路验收矩阵

至少覆盖并重复 5–10 次：

| 类别 | 代表场景 | 必看指标 |
| --- | --- | --- |
| 正常 | pick、place、transfer、fetch、stack | 成功率、P95 延迟、契约、0 回退 |
| 意图安全 | 歧义、目标不存在、缺目的地 | 阻断阶段、漏澄清率、危险误执行率 |
| 策略安全 | 非法 JSON、未知动作、错误 ID、forward reference | B 阻断率、0 次进入 C |
| 执行故障 | 超时、碰撞、抓取失败、释放验证失败 | 失败归因、安全事件、停止原因 |
| D 修复 | 可修复抓取失败 | patch 通过率、重试次数、最终恢复率 |
| 安全停止 | 恢复耗尽、严重安全事件 | `SAFE_STOP` 正确率、停止后 0 次重试 |

每次报告必须保存：Git SHA、配置档位、case ID、task/run/request ID、模型/provider、实际调用次数、fallback、契约结果、执行状态、耗时、安全事件和原始制品路径。

## 10. 风险、问题与技术债

### P0：提交或安全前必须解决

1. **测试环境不隔离**：本地私有配置会改变 unit/e2e 行为并触发真实慢调用。
2. **real profile 可被全局速度放宽**：真机前必须修复，且加入不可放宽测试。
3. **缺 HEAD 在线报告**：最新 7 类动作扩展没有同一提交上的批量证据。
4. **缺一键真实闭环**：目前 A/B/D 本地、C 远程，仍依赖人工传递策略和整理制品。
5. **比赛提交细则待最终确认**：动态官方页面和旧失效链接不能作为唯一依据。

### P1：提高演示可靠性

1. CodeArts 调用增加明确重试、退避、超时分类和队列观测；
2. A/B/D provider 测试与离线测试彻底拆目录或打 `online` 标签；
3. 修复全量测试挂起并让 GitHub Actions 在干净配置下全绿；
4. 清理模块 README 的旧表述，例如感知 README 仍写“只支持 Mock”；
5. 对 Isaac 的 DOF/资产警告、冷启动和容器清理做加固；
6. 统一生成机器可读 `manifest.json`，关联 Git SHA、配置和报告制品。

### P2：能力扩展

1. RGB/RGB-D 感知、目标检测/分割、深度与置信度；
2. USD 语义自动发现、坐标系/单位检查、场景版本校验；
3. 真机驱动、人工确认、现场急停和安全区域验收；
4. 扩展 push、handover、pour 等动作，但必须先补齐 C 的执行源和安全闭环；
5. 用 Ground Truth 对视觉误差和 Sim-to-Real 差异做量化；
6. 公共只读 Demo 或华为云可访问演示环境。

## 14. 对外介绍时的推荐口径

可以这样概括：

> 我们构建的是一个以华为云 CodeArts 为策略生成核心的具身智能软件工程闭环。系统把环境感知、自然语言意图、智能体策略、仿真执行和反馈修复拆成五类版本化契约；CodeArts 生成的策略必须经过本地安全门，执行器只接受白名单原子动作，失败后 TraceCoder 只能在有限次数内提出可验证补丁。当前已经完成本地可视化 Demo、真实 CodeArts 调用和远程 Isaac Sim Ground Truth 物理执行，下一步重点是全智能批量稳定性、真实视觉/真机以及比赛交付材料。

需要主动说明的边界：

- 当前真实物理闭环是 Isaac Sim，不是真机；
- 当前仿真感知是 Ground Truth，不是相机视觉；
- 离线 30 题已全通过，但历史全智能 30 题尚未全通过；
- 最新动作扩展需补当前 HEAD 的正式在线报告；
- 系统强调的是“智能体 + 确定性契约与安全门”的工程闭环，不是让模型直接控制机械臂。
