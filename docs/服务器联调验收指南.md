# C 模块 · 服务器联调验收指南

> 当前主线：`main`（2026-08-21）
> 前置：Isaac 后端 + local/sim/real 配置 + stack_on 已集成；C 相关单元测试和远程 CUDA 验收已通过。

本文指导在服务器 Isaac Sim / 真机环境下，用**新 executor 链路**完成 C 模块验收。
当前 Isaac Sim 验收由官方 `FrankaPickPlace` 控制器经
`FrankaPickPlaceDriver` 适配到 executor；不再用 mock 位姿替代物理结果。

---

## 一、验收判据（P0/P1）

同一条 `strategy.v1` 在 Mock 和 Isaac Sim 下产出**可对照的 `execution.v1`**：

- `status == SUCCEEDED`
- `cube_before` / `cube_after` 位姿变化（`cube_moved_m > 0`）
- `steps` 含五步原子动作记录，detect 步骤带 `pose` 证据
- `trajectory_points` 含关节轨迹
- `provenance.backend == "isaac"`
- 安全事件 `safety_events` 为空（正常任务）
- `cube_before` / `cube_after` 必须由 Isaac Sim prim 回读；`release` 还必须通过释放后位姿校验，不能只看后端逻辑状态

## 二、一键运行（推荐）

在 Windows PowerShell 中，先连接校园 VPN，再执行：

```powershell
.\tools\run_remote_isaac_acceptance.ps1 `
  -Server 10.16.0.40 -Port 5122 -User stu_01 -KeepRemote
```

脚本会自动打包当前契约、适配器、后端和验收入口，创建带时间戳的远程目录，
上传 A/B 策略，启动 Isaac Sim 6.0 CUDA 容器并下载 `execution.json` 与
`progress.jsonl`。它不会读取或上传本地密钥、CSV、`.env` 或 TraceCoder 凭证。
首次运行可输入 SSH 密码；后续建议改用 SSH 公钥，减少交互式输入。

## 三、手工传输到服务器（排障备用）

```bash
# 本机（Windows，PowerShell）—— 脚本已随仓库在 tools/ 下，无需单独传

ssh -p 5122 stu_01@10.16.0.40 "sudo chown -R 1234:1234 /data/stu_01/workspace"
```

## 四、容器内运行（Isaac Sim 6.0，无头 + CUDA）

```bash
docker run --rm \
  --entrypoint bash \
  --gpus '"device=0"' \
  --network none \
  -u 1234:1234 \
  -e ACCEPT_EULA=Y \
  -e PRIVACY_CONSENT=N \
  -e ISAACSIM_ASSET_ROOT=/isaacsim_assets/Assets/Isaac/6.0 \
  -v /data/stu_01/workspace/codearts-executor-isaac-v2:/workspace \
  -v /data/stu_01/isaac_assets:/isaacsim_assets:ro \
  nvcr.io/nvidia/isaac-sim:6.0.0 \
  -lc 'cd /isaac-sim && ./python.sh /workspace/tools/run_executor_acceptance.py --device cuda --result-dir /workspace/results --/app/headless=true --/persistent/isaac/asset_root/default=/isaacsim_assets/Assets/Isaac/6.0'
```

> 关键：镜像默认 entrypoint 是流式应用，**必须 `--entrypoint bash` 覆盖**再
> `cd /isaac-sim && ./python.sh ...`；`--/app/headless=true` 与资产路径两个参数都要。
> 资产目录名以宿主机实际为准（`/data/stu_01/isaac_assets`）。

可选参数 `--placement-mode direct|stack_on`（默认 direct）。

## 七、运行注意事项（务必先读）

1. 验收脚本使用 `FrankaPickPlaceDriver` 适配 NVIDIA 官方
   `FrankaPickPlace` 控制器；它与 `ExecutorAdapter → IsaacSimBackend →
   RobotBackend` 共用同一条真实执行链路。`OmniDriver` 仍保留给通用差分 IK
   场景，但不作为本验收脚本的主驱动。
2. 服务器验收使用 `--device cuda`。本机 CPU 物理在冷启动阶段明显过慢；CUDA
   运行的首个 approach 阶段实测约 120–135 s，因此 `sim` profile 的有限动作
   时限为 180 s，并未关闭超时或安全停止。
3. 运行前确保 GPU 0 可用；无头截图失败不影响验收：以物体前后位姿、真实关节
   轨迹、释放后位姿校验和安全事件为准。

---

## 八、真机（real profile）注意事项

真机后端 `RealRobotBackend` 默认 `require_human_confirmation=True`：
运动动作前必须 `confirm(operator_id)`，否则返回 `HUMAN_CONFIRMATION_REQUIRED`。
真机限速 0.05 m/s、工作空间 x/y ±0.3、z 0.02–0.45（`integration/config/profiles/real.toml`）。

---

## 九、全链路 A→B→C→D

C 的 executor 已通过 `from_profile` 接入 `integration/pipeline.py`（`adapters["executor"]`）。
远程服务器只负责 C 的真实仿真执行；A/B/D 在本地或联调机生成并校验
`strategy.v1` 后，通过 `--strategy-file` 交给 C。C 侧无需改变接口；真实
机器人接入前仍必须完成传感器、驱动、人工确认和现场安全验收。
