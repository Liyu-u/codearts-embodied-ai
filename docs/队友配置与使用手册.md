# 具身智能系统队友配置与使用手册

本文面向第一次拉取本仓库的队友，说明如何完成本地配置、启动 Demo、使用 A/B/C/D 闭环，以及如何进行离线测试、真实大模型测试和 Isaac Sim 联调。

## 1. 系统组成

本仓库的主流程如下：

~~~text
自然语言指令 + 感知场景
        ↓
A：意图理解        → task.v1
        ↓
B：CodeArts 策略  → strategy.v1
        ↓
C：Mock / Isaac / 真机执行 → execution.v1
        ↓
D：TraceCoder 反馈 → feedback.v1
~~~

需要配置大模型或智能体的是 A、B、D 三个模块；C 模块主要配置执行环境和安全参数。

## 2. 第一次使用前的准备

### 2.1 最低环境

本地离线 Demo 需要：

- Git；
- Windows PowerShell；
- Python 3.11 或更高版本；
- 能够安装 Python 依赖的网络环境。

真实智能模式还需要：

- A/D 使用的 OpenAI 兼容模型服务和 API Key；
- B 使用的 CodeArts CLI、账号权限和模型/智能体权限。

Isaac Sim 和真机不是本地 Demo 的必需项，见本文第 8 节。

### 2.2 拉取仓库

~~~powershell
git clone <仓库地址>
cd codearts-embodied-ai
~~~

如果仓库目录名称不同，请进入实际仓库根目录。后续命令都应在包含 README.md、modules/ 和 tools/ 的目录执行。

## 3. 一键配置

首次配置直接运行：

~~~powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup.ps1
~~~

脚本会自动：

1. 创建 .venv Python 虚拟环境；
2. 安装 requirements.txt；
3. 询问 DeepSeek API Key、模型和运行模式；
4. 询问 CodeArts AK/SK，并保存到本机用户环境；
5. 生成三个本地配置文件；
6. 自动执行配置体检。

配置文件如下：

| 本地文件 | 对应模块 | 是否提交到 Git |
|---|---|---|
| .env | A 意图理解和执行安全域 | 否 |
| tracecoder_llm.env | D TraceCoder | 否 |
| codearts.env | B CodeArts CLI | 否 |
| .env.example | A 配置模板 | 是 |
| tracecoder_llm.env.example | D 配置模板 | 是 |
| codearts.env.example | B 配置模板 | 是 |

真实密钥只写入本机被 Git 忽略的文件，不要把它们复制到聊天、提交记录或公共文档中。

### 3.1 日常开发配置

日常推荐使用规则回退模式：

~~~powershell
.\tools\setup.ps1 `
  -IntentMode hybrid `
  -TraceCoderMode optional `
  -CodeArtsMode auto
~~~

含义是：有模型或智能体时优先调用，调用失败时保留安全的本地规则路径。

### 3.2 正式智能模式

正式演示或严格验收使用：

~~~powershell
.\tools\setup.ps1 `
  -IntentMode llm `
  -TraceCoderMode required `
  -CodeArtsMode required
~~~

该模式下，A、B、D 任一真实 Provider 调用失败都会明确报错或阻断，不会静默回退到规则。

### 3.3 完全离线配置

没有 API Key、CodeArts 或网络时使用：

~~~powershell
.\tools\setup.ps1 `
  -IntentMode rule `
  -TraceCoderMode off `
  -CodeArtsMode off
~~~

这适合开发接口、运行单元测试和检查 C Mock 执行链路。

### 3.4 重复配置

配置脚本可以重复运行。已有配置通常会被保留，重新运行时只需要修改想改变的模式或模型。

如果只想检查而不安装依赖：

~~~powershell
.\tools\setup.ps1 -NonInteractive -SkipInstall
~~~

如果暂时不配置 CodeArts：

~~~powershell
.\tools\setup.ps1 -SkipCodeArts
~~~

## 4. 配置体检

普通体检不会调用在线模型：

~~~powershell
.\.venv\Scripts\python.exe tools\doctor_config.py
~~~

体检内容包括：

- Python 版本；
- .env、tracecoder_llm.env、codearts.env 的字段命名空间；
- A 的模型、Key 和 RIA_PLANNER_ENGINE；
- D 的模型、Key 和 TRACECODER_LLM_MODE；
- B 的 CodeArts CLI、运行模式和审查策略。

如果要真实检查 CodeArts 的模型和智能体可见性：

~~~powershell
.\.venv\Scripts\python.exe tools\doctor_config.py --live-codearts
~~~

该命令会调用：

~~~text
codearts models
codearts agent list
~~~

## 5. 启动本地 Demo

### 5.1 默认启动

~~~powershell
.\demo\start_demo.ps1
~~~

浏览器打开：

~~~text
http://127.0.0.1:8765/
~~~

Demo 默认使用 C Mock 执行器，并通过页面展示感知、意图、策略、执行和反馈结果。

### 5.2 指定端口

如果 8765 端口被占用：

~~~powershell
.\demo\start_demo.ps1 -Port 8766
~~~

### 5.3 让 Demo 使用真实 CodeArts

~~~powershell
.\demo\start_demo.ps1 `
  -CodeArtsMode required `
  -CodeArtsPolicy quality `
  -CodeArtsModel <模型名>
~~~

可选策略：

- planner：只调用一次规划；
- quality：规划后增加一次独立审查；
- max：规划后增加两次审查。

### 5.4 停止 Demo

start_demo.ps1 会输出进程 PID。停止命令：

~~~powershell
Stop-Process -Id <PID>
~~~

## 6. 三个智能模块的配置含义

### 6.1 A：意图理解

配置文件：.env

关键字段：

~~~text
RIA_DEEPSEEK_API_KEY       # API Key
RIA_DEEPSEEK_BASE_URL      # OpenAI 兼容服务地址
RIA_DEEPSEEK_MODEL         # 正式建议 deepseek-v4-flash
RIA_DEEPSEEK_TEMPERATURE   # A 建议 0.0
RIA_DEEPSEEK_THINKING      # disabled（低延迟 JSON 语义路径）
RIA_DEEPSEEK_TIMEOUT_S     # A 建议 15 秒
RIA_DEEPSEEK_MAX_RETRIES   # A 建议 1
RIA_DEEPSEEK_MAX_TOKENS    # A 建议 2400
RIA_PLANNER_ENGINE         # rule / llm / hybrid；正式建议 llm
RIA_LLM_FAILURE_POLICY     # fallback / block；正式 llm 建议 block
RIA_LLM_CACHE_ENABLED      # 精确指令缓存
RIA_LLM_CACHE_MAX_ENTRIES  # 默认 128
~~~

修改 A 配置后，需要重新启动 Demo 或 Python 进程。

调用方式：integration.adapters.intent.run() 先由
SemanticCompiler 调用 LLM 生成语义候选，再由本地规则、关系校验和场景
grounding 生成唯一可执行任务。正式 RIA_PLANNER_ENGINE=llm 且
RIA_LLM_FAILURE_POLICY=block 时，Provider 未配置、超时或返回非法 JSON
直接返回 BLOCKED；候选字段校验失败仍走安全的规则候选，不把模型输出直接当作
物理实体 ID。

### 6.2 B：CodeArts 策略生成

配置文件：codearts.env

关键字段：

~~~text
CODEARTS_CLI
CODEARTS_STRATEGY_MODE     # off / auto / required
CODEARTS_STRATEGY_AGENT
CODEARTS_STRATEGY_MODEL
CODEARTS_STRATEGY_POLICY   # planner / quality / max
CODEARTS_STRATEGY_TIMEOUT_S
CODEARTS_CLI_PURE
~~~

CodeArts CLI 也需要能够在终端中直接运行：

~~~powershell
codearts models
codearts agent list
~~~

如果自定义智能体没有文件写入或 Shell 权限，应优先使用只读、受限的智能体配置。

### 6.3 D：TraceCoder 反馈修复

配置文件：tracecoder_llm.env

关键字段：

~~~text
TRACECODER_LLM_MODE       # off / optional / required；正式建议 required
TRACECODER_LLM_MODEL       # 正式建议 deepseek-v4-flash
TRACECODER_LLM_BASE_URL
TRACECODER_LLM_API_KEY
TRACECODER_LLM_TIMEOUT_S   # D 建议 20 秒
TRACECODER_LLM_MAX_RETRIES # D 建议 1
TRACECODER_LLM_TEMPERATURE # D 建议 0.0
TRACECODER_LLM_MAX_TOKENS  # D 建议 4096
TRACECODER_LLM_JSON_MODE   # true
TRACECODER_LLM_THINKING    # enabled
TRACECODER_LLM_REASONING_EFFORT # low
TRACECODER_MAX_REPAIR_ATTEMPTS # 默认 2
~~~

D 的配置必须放在独立文件中，不能复制到根目录 .env。否则 A 的严格配置解析可能报告 extra_forbidden。

调用方式：integration.adapters.tracecoder.run() 将 execution.v1 交给
process_policy；每轮按 observation → diagnosis → repair 顺序调用一次模型，
patch 先通过本地白名单和安全校验，再交给 C 重试。最多修复 2 轮，required
模式下任一角色调用失败或 patch 不合法都会返回 LLM_REQUIRED_FAILED，不会
偷偷换成规则 patch。

## 7. 测试和提交前检查

### 7.1 离线全量测试

~~~powershell
$env:RIA_PLANNER_ENGINE="rule"
$env:CODEARTS_STRATEGY_MODE="off"
$env:TRACECODER_LLM_MODE="off"
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -q
~~~

如果命令行中已经有在线模式环境变量，先执行上面的三行，避免测试意外产生模型调用费用或受网络影响。

### 7.2 常用分层测试

~~~powershell
# 契约测试
.\.venv\Scripts\python.exe -m unittest discover -s tests/contract -t . -v

# 集成测试
.\.venv\Scripts\python.exe -m unittest discover -s tests/integration -t . -v

# Demo 测试
.\.venv\Scripts\python.exe -m unittest tests.e2e.test_demo_scenarios tests.e2e.test_demo_quality tests.e2e.test_demo_http -v
~~~

### 7.3 提交前规则

- 不提交 .env、tracecoder_llm.env、codearts.env；
- 不提交 API Key、AK/SK、SSH 密码或个人路径；
- 不为了测试通过而关闭安全校验；
- 修改契约时同步修改 Schema、适配器和测试；
- 真机配置只能收紧安全边界，不能擅自放宽限速、限力和工作空间。

## 8. Isaac Sim 和真机联调

### 8.1 本地 Mock

本地开发优先使用 local profile，不需要服务器：

~~~text
backend = mock
~~~

### 8.2 远程 Isaac Sim

远程仿真需要：

- 校园 VPN；
- SSH 地址、端口和用户名；
- 远程 Docker；
- NVIDIA GPU；
- Isaac Sim 6.0.0 镜像；
- Isaac Sim 资产目录。

启动示例：

~~~powershell
.\tools\run_remote_isaac_acceptance.ps1 `
  -Server <服务器地址> `
  -Port <SSH端口> `
  -User <用户名> `
  -KeepRemote
~~~

脚本只上传代码、契约和策略文件，不上传本地密钥文件。

### 8.3 真机

真机使用 real profile，默认要求：

- 人工确认；
- 更低线速度和夹爪力；
- 更小工作空间；
- 急停和碰撞检查开启；
- 真实传感器、驱动和机器人状态已经现场验收。

没有现场负责人确认时，不要切换到真机后端。

## 9. 常见问题

### Python not found

安装 Python 3.11+，或指定 Python 路径：

~~~powershell
.\tools\setup.ps1 -PythonPath "C:\Path\To\python.exe"
~~~

### PowerShell 禁止执行脚本

使用：

~~~powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup.ps1
~~~

### extra_forbidden 或 Settings 校验失败

通常是把 B/D 配置复制到了根目录 .env。不要手工混合配置，重新运行：

~~~powershell
.\tools\setup.ps1
~~~

### A 没有调用大模型

检查：

~~~text
RIA_DEEPSEEK_API_KEY
RIA_PLANNER_ENGINE=llm 或 hybrid
~~~

### B 报 CODEARTS_CLI_NOT_FOUND

检查：

~~~powershell
Get-Command codearts
codearts models
~~~

如果 CLI 已安装但找不到，重新打开终端，或在 codearts.env 中填写完整的 CODEARTS_CLI 路径。

### D 报未配置 API Key 或模型

检查 tracecoder_llm.env 中的：

~~~text
TRACECODER_LLM_API_KEY
TRACECODER_LLM_MODEL
TRACECODER_LLM_MODE
~~~

修改后重新启动进程。

### Demo 端口被占用

换端口：

~~~powershell
.\demo\start_demo.ps1 -Port 8766
~~~

### Isaac Sim 连接失败

依次检查 VPN、SSH 端口、Docker、GPU、资产目录和远程用户权限。先完成本地 Mock 验收，再排查远程仿真，不要直接用真机排查软件配置问题。

## 10. 推荐工作顺序

~~~text
拉取仓库
  ↓
运行 setup.ps1
  ↓
运行 doctor_config.py
  ↓
运行离线单元/契约测试
  ↓
启动 Mock Demo
  ↓
启用 A/B/D 真实 Provider 做小范围冒烟
  ↓
远程 Isaac Sim 验收
  ↓
现场负责人确认后再进行真机测试
~~~

遇到问题时，请同时提供：运行命令、doctor_config.py 输出、模块模式、task_id 和脱敏后的错误信息。不要提供 API Key、AK/SK 或 SSH 密码。
