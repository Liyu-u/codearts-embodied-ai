# 华为云网站真实 A/B/C/D–Isaac 闭环升级设计

## 1. 目标与验收边界

将当前以 Mock 数据和静态占位为主的演示网站升级为真实任务控制与展示系统。用户在华为云网站选择经过验证的预设场景并输入自然语言后，系统在华为云运行 A、B、D 和统一编排逻辑，通过第三台校园网电脑把 C 的策略交给学校服务器上的 Isaac Sim 执行，再把实时进度、执行证据和最终位姿回传华为云。网站同步展示 A→B→C→D 状态和现有仿真直播。

本期不接真实机械臂，不把 Mock 结果显示成真实仿真结果，不承诺尚未制作或验证的独立 USD 场景。第一版以现有、已经真实执行验证的 Isaac 工作台为基础，通过不同初始布局、目标物、目的地区域和故障配置形成 3–5 个预设场景。

一次运行只有同时满足以下条件才显示为“真实闭环成功”：

- A、B、D 的必需智能调用均有真实 Provider request ID，且未使用 fallback；
- `perception.v1`、`task.v1`、`strategy.v1`、`execution.v1`、`feedback.v1` 均通过契约校验；
- 感知哈希、策略哈希、`task_id` 和 `run_id` 连续一致；
- C 的来源为 Isaac，所有必要动作完成，最终位姿来自 Isaac Ground Truth 或经声明的真实传感器来源；
- 最终位姿满足任务目标，且没有终止事件之后的成功动作；
- 网站能够恢复并显示该运行的真实状态、事件和证据摘要。

## 2. 部署拓扑

系统由三个部署域组成。

### 2.1 华为云服务器

运行：

- 网站静态资源；
- 任务编排 API；
- A 意图理解；
- B CodeArts 策略生成；
- D TraceCoder 结果验证；
- 任务队列、状态、事件和证据元数据存储；
- 浏览器 WebSocket/SSE 实时事件接口；
- MediaMTX/HLS 反向代理和现有直播入口。

API Key、CodeArts 凭证和模型配置仅保存在服务器环境或受限配置文件中。浏览器只读取脱敏状态。

### 2.2 第三台校园网电脑

运行一个轻量执行中继。它不负责意图理解、策略生成或结果判定，只负责：

- 主动通过 HTTPS 向华为云领取待执行的 C 任务；
- 校验任务签名、租约和策略哈希；
- 使用现有 SSH/SCP 通道访问 `10.16.0.40:5122`；
- 启动或调用学校服务器上的 Isaac 任务；
- 增量回传进度事件；
- 上传 `perception.json`、`execution.json`、`final_pose.json` 和必要日志摘要；
- 保留现有 SSH RTSP 中继与推流方式，不改变视频网络配置。

中继只建立出站连接，不开放校园网入站端口。

### 2.3 学校服务器

运行 Isaac Sim 6.0、GPU 容器、场景资产、Ground Truth/相机感知和真实执行器。它不直接暴露给公网，继续由第三台电脑通过 SSH/SCP 管理。

## 3. 真实运行数据流

1. 浏览器读取场景目录，只显示后端标记为 `available` 且通过 Isaac 资产检查的场景。
2. 用户选择场景；华为云创建场景准备任务。
3. 第三台电脑领取任务并让 Isaac 加载或重置场景，回传 `SCENE_READY`。
4. 网站在收到真实就绪事件后允许提交自然语言任务。
5. 华为云创建不可变 `run_id`，记录场景版本和指令。
6. C 先从同一 Isaac 场景生成 `perception.v1` 并回传华为云。
7. 华为云 A 使用本次感知生成 `task.v1`。歧义、未知目标或 Provider 失败时 fail-closed。
8. 华为云 B 使用同一任务和感知生成、审查并验证 `strategy.v1`。失败时不下发 C。
9. 华为云把带哈希的 C 执行任务放入队列；第三台电脑领取并续租。
10. Isaac 执行策略，第三台电脑持续回传动作开始、完成、安全停止和心跳事件。
11. 执行结束后，第三台电脑上传执行证据和最终位姿。
12. 华为云验证哈希和契约后运行 D，生成 `feedback.v1`。只有经过策略门禁的有限修复才能形成一次新的 C 执行尝试。
13. 编排器生成最终状态；网站显示真实来源、动作结果和验证结论。

每个事件必须携带 `event_id`、`run_id`、`task_id`、`timestamp`、`stage`、`status`、`sequence` 和 `provenance`。服务器按 `event_id` 去重，并按 `sequence` 排序。

## 4. 华为云接口

### 4.1 浏览器接口

- `GET /api/health`：分别返回云编排、A/B/D、执行中继、Isaac、直播状态；不得用一个总布尔值掩盖部分故障。
- `GET /api/scenarios`：返回已验证场景、版本、能力、当前可用性和直播映射。
- `POST /api/runs`：创建运行，输入 `scene_id` 和 `instruction`，返回 `run_id`。
- `GET /api/runs/{run_id}`：返回可恢复的运行快照。
- `GET /api/runs/{run_id}/events`：返回历史事件。
- `GET /api/events?run_id=...`：WebSocket 或 SSE 实时事件。
- `POST /api/runs/{run_id}/commands`：仅开放真实实现且有安全语义的取消/停止；第一版不展示未实现的暂停和急停。
- `GET /api/livestream`：继续返回现有 HLS 地址，并增加播放健康和更新时间。
- `GET /api/model-config`：仅返回模块模式、模型和凭证是否已配置。
- `PUT /api/model-config`：仅管理员使用，原始 Key 不返回浏览器。

### 4.2 执行中继接口

- `POST /api/relay/register`：中继注册和能力上报。
- `POST /api/relay/heartbeat`：中继、SSH、Isaac、GPU 和直播状态心跳。
- `POST /api/relay/jobs/claim`：长轮询领取一个任务并获得有时限租约。
- `POST /api/relay/jobs/{job_id}/events`：批量、幂等上传进度事件。
- `POST /api/relay/jobs/{job_id}/artifacts`：上传受限大小的 JSON 证据和日志摘要。
- `POST /api/relay/jobs/{job_id}/complete`：提交成功、失败或安全停止结果。
- `POST /api/relay/jobs/{job_id}/lease`：长任务续租。

中继使用独立令牌或双向认证。任务领取和上传必须校验 `job_id`、租约、`run_id`、策略摘要和允许的文件清单。不得提供任意 shell 命令接口。

## 5. 任务状态机与错误处理

运行状态固定为：

`CREATED → PREPARING_SCENE → PERCEIVING → UNDERSTANDING → PLANNING → EXECUTING → VERIFYING → SUCCEEDED`

任意阶段可进入 `BLOCKED`、`FAILED`、`SAFE_STOPPED` 或 `CANCELLED`。终态不可被后续迟到事件改写。

- Provider 超时、无效输出或 fallback：阻断，不进入下一模块；
- 中继离线：任务保持排队或在租约到期后安全失败；
- SSH/Isaac 断开：C 返回通信失败，禁止伪造成功；
- 碰撞、越界、超速、力限制或急停：立即安全停止，不执行后续动作；
- 页面刷新：通过运行快照和历史事件恢复；
- 重复事件：按 `event_id` 幂等处理；
- 重复领取：租约确保同一 C 任务同一时刻只有一个中继执行；
- D 修复：最多一次网站可见的受限重试，且保留原始失败证据。

## 6. 前端信息架构

首页只保留与真实闭环直接相关的内容：

- 顶部：云服务、中继、Isaac 和直播四项真实状态；
- 左侧：经过验证的预设场景列表、场景准备状态、自然语言输入和执行按钮；
- 中央：现有 HLS 直播画面，显示直播健康、延迟提示和重连状态；
- 直播下方：A、B、C、D 四阶段状态、耗时、真实来源和当前说明；
- 右侧：C 当前动作、步骤进度、任务目标、最终结果和安全事件；
- 底部：当前运行的必要事件时间线和证据摘要。

删除无真实数据来源的 CPU、内存、任务总数、AUBO 型号/IP/负载、固定关节角、固定安全状态、语音输入、2D、俯视相机、碰撞体、检测框、虚构数据集/模型/权限/审计统计，以及只返回“已接收”但没有控制效果的按钮。

所有状态必须来自 API。没有数据时显示“未连接”或“无数据”，不生成看似真实的默认数值。

## 7. 直播保护策略

现有 RTSP→第三台电脑→华为云→HLS 链路保持独立，任务系统不得重启或修改直播进程。

- 新 API 和中继先使用独立端口部署；
- 不修改现有 MediaMTX 路径、推流凭证、SSH RTSP 中继和反向代理位置；
- 部署前后分别验证 HLS 清单、分片更新和网页播放；
- 任务系统只读取直播健康状态，不拥有停止直播的权限；
- 前端更新失败可回退静态资源，不回退或重启直播；
- 如果直播暂时不可用，任务系统可以按配置阻止录像演示，但不得把缓存画面标记为实时画面。

## 8. 安全与权限

- 所有公网写接口需要认证、权限、速率限制和审计；
- 模型 Key、SSH 私钥和推流凭证不进入前端、任务数据、日志或 Git；
- 第三台电脑保存专用最小权限 SSH Key 和中继凭证；
- 上传证据仅允许 JSON/JSONL 和受限日志文本，校验大小和路径；
- 禁止云端向中继下发任意命令；中继只执行预定义作业类型；
- C 的安全判断在执行后端，前端不能绕过；
- 第一版面向受控演示环境，公网发布前必须启用登录和管理员配置权限。

## 9. 存储与可观测性

第一版使用服务器本地持久化数据库和按 `run_id` 隔离的证据目录，接口层隐藏具体实现。任务表保存状态、时间、场景、指令摘要和来源；事件表保存有序事件；证据目录保存经过允许列表校验的契约文件。

日志必须能回答：任务由谁创建、A/B/D 调用了哪个 Provider、C 由哪个中继和 Isaac 实例执行、何时发生重试或安全停止、最终结论使用了哪些证据。敏感字段必须脱敏。

## 10. 测试与验收

### 10.1 自动测试

- 现有 319 项回归保持通过；
- 新增状态机、任务租约、幂等事件、证据上传和权限测试；
- 新增中继断线重连、SSH 失败、Isaac 超时和重复领取测试；
- 新增前端场景选择、页面刷新恢复、实时事件和失败展示测试；
- 新增直播健康检查，但不让自动测试停止现有直播。

### 10.2 真实验收

至少完成：

- 3 个正常场景，每个重复 3 次；
- 1 个目标歧义场景，必须在 A 阻断；
- 1 个非法或缺失策略场景，必须在 B/C 边界阻断；
- 1 个碰撞或安全限制场景，必须安全停止且无后续成功动作；
- 1 个可恢复故障场景，最多一次受限重试；
- 页面、事件、证据和直播时间线一致；
- A/B/D 有真实 request ID，C 有 Isaac 来源和最终位姿；
- 第三台电脑和页面分别断线后能够恢复状态；
- 整个录制过程直播不断流。

## 11. 实施与切换顺序

1. 在本地实现并测试云端状态机和 API；
2. 实现第三台电脑中继，复用现有 SSH/SCP 执行代码；
3. 使用测试端口部署云端 API，不修改正式网站；
4. 跑通中继→Isaac→云端证据闭环；
5. 增加浏览器实时事件和精简后的新前端；
6. 在测试 URL 完成真实场景、断线和安全验收；
7. 验证现有 HLS 在改造前后连续可播放；
8. 备份当前网站静态资源和服务配置；
9. 切换正式网站到新 API 和前端；
10. 完成一条正式环境真实任务；失败则仅回退网站/API，不触碰直播链路。

## 12. 非目标

- 本期不接真实机械臂；
- 不在浏览器中直接连接 DeepSeek、CodeArts、SSH 或 Isaac；
- 不把所有 Mock 场景自动声明为真实 Isaac 场景；
- 不实现没有后端支持的装饰性控制功能；
- 不为了任务系统重构或替换当前已工作的直播传输方案。
