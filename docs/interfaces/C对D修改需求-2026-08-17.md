# C 对 D 的正式接口修改要求

> 发起人：C（Isaac Sim/执行，吴昌庆）
>
> 接收方：D（TraceCoder/评估修复）
>
> 优先级：P0，B→C 字段变更后必须同步

## 1. D 必须迁移的字段

D 在读取、静态检查、轻量仿真、经验匹配和 patch 生成时统一使用：

- `detect_object.arguments.object_id`
- `move_to_object.arguments.object_id`
- `grasp.arguments.object_id`
- `move_to_target.arguments.destination_id`
- `release.arguments = {}`

删除正式路径中的 `object_name` 和 `target`。不要在 D 内部把稳定 ID 改成 `obj_1`、`target_1` 等临时编号。

重点排查文件：

- `modules/evaluator/tracecoder/defaults.py`
- `modules/evaluator/tracecoder/static_checker.py`
- `modules/evaluator/tracecoder/simulator.py`
- `modules/evaluator/tracecoder/agents.py`
- `modules/evaluator/tracecoder/experience.py`
- `integration/adapters/tracecoder.py`
- D 的测试、fixture、演示样例和前端映射

## 2. C 给 D 的执行事实

D 接收 `{task, strategy, execution}`。最终事实必须来自 `execution.v1`，尤其是：

- 顶层 `status = SUCCEEDED | FAILED | SAFE_STOP`
- `steps[].step_id/phase/action/arguments/status/reason/duration_ms`
- `trajectory_points`
- `total_duration_ms`
- `safety_events`

D 的内部模拟只能用于候选 patch 预检查，不能覆盖真实 C 执行结果。如果真实 `execution.status=SUCCEEDED`，不得仅因轻量仿真 ID 不一致而判定最终失败。

## 3. 错误和安全规则

至少识别并保留以下 C 错误：

- `INVALID_ARGUMENT:*`：策略参数不符合正式接口，责任在 B/D patch。
- `UNRESOLVED_REFERENCE:*`：引用不存在或引用尚未产生。
- `OBJECT_NOT_FOUND:<id>`：场景没有该稳定对象 ID。
- `INVALID_DESTINATION:<id>`：目的地不存在或 C 判定不可作为安全目标区。
- `OBJECT_NOT_GRASPABLE:<id>`、`OBJECT_NOT_APPROACHED`、`NOT_HOLDING_OBJECT`。
- `RECOVERY_EXHAUSTED`、`ACTION_LIMIT_EXCEEDED` 和安全事件。

出现 `SAFE_STOP` 或任意严重安全事件时：

- `retryable` 必须为 `false`；
- 不得生成自动重执行 patch；
- 不得通过 patch 删除安全步骤、清除安全事件或把状态改成成功；
- 只能给出人工检查建议，等待显式复位。

## 4. Patch 白名单

D 的 patch 只能生成 C 已支持的 `strategy.v1` 字段和五个动作。每个 patch 必须满足：

1. `task_id` 不变；
2. 只引用 task/perception 中真实存在的稳定 ID；
3. `step_id` 唯一，引用指向前序步骤；
4. `object_id`、`destination_id` 字段正确；
5. 有限步骤、有限恢复和有限重试；
6. `code` 为空；
7. 经过与 B 原始策略相同的本地 schema、动作、实体和安全校验。

错误 patch 示例（必须拒绝）：

```json
{"action": "move_to_target", "arguments": {"target": "zone_001"}}
```

正确 patch 示例：

```json
{"action": "move_to_target", "arguments": {"destination_id": "zone_001"}}
```

## 5. TraceCoder 大模型正式验收

D 需要把不存在的外部 `src.generation` 解耦为统一 Provider，并支持：

- `TRACECODER_LLM_MODE=off|optional|required`
- `TRACECODER_ALGORITHM=rules|llm|hybrid`

正式验收使用 `required`，不得静默退回规则。每次模型调用记录模型、request ID、耗时、错误、是否回退、候选来源、最终选择来源和 patch 校验结果。覆盖：正常任务、抓取失败、目标未达成、无效修复、持续失败安全停止。

## 6. D 的完成标准

- [ ] 静态目录、模拟器、Agent、经验库和测试全部理解 `object_id/destination_id`。
- [ ] D 不再生成或接受正式字段 `object_name/target`。
- [ ] `execution.v1` 是最终事实，内部模拟不会覆盖真实结果。
- [ ] 普通失败可生成一个受限候选 patch；`SAFE_STOP` 永不自动重试。
- [ ] 正常成功、可修复失败、非法 patch、持续失败安全停止四类测试通过。
- [ ] 与 A/B/C 使用同一组稳定对象和目的地 ID fixture。

D 合并修改后应运行全量测试，并把一份失败前策略、`execution.v1`、`feedback.v1`、修复后策略及第二次执行结果交给 C 复核。
