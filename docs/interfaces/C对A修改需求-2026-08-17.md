# C 对 A 的正式接口要求

> 发起人：C（Isaac Sim/执行，吴昌庆）
>
> 适用阶段：第一阶段 `READY + pick_and_place`
>
> 结论：A 给出的 `perception_observation 1.0.0` 字段结构保持不变，C 已增加兼容转换器。

## 1. A 不需要改的内容

A 继续按已经给出的格式发送：

- `schema_version = "1.0.0"`
- `message_type = "perception_observation"`
- `observation_id`、`scene_id`、`timestamp`、`clock_domain`
- `coordinate_system`
- `source.module/pipeline_version/sensor_ids`
- `objects[].object_id/category_candidates/pose/geometry/appearance/tracking`
- 可选的 `simulation_metadata`

完整可执行样例以仓库中的 `testdata/integration/a_perception_observation_v1.json` 为准。C 已经把该样例加入自动化契约测试。

## 2. A 必须保证的语义

1. 第一阶段每条消息是当前场景的完整快照，不是只包含变化对象的增量消息。
2. `object_id` 在同一个 `scene_id` 的整个任务期间稳定、唯一且不复用。A 不得在相邻帧中给同一对象重新编号。
3. 可被抓取的目标、放置区域和会影响规划的障碍物都必须出现在 `objects` 中。B、C、D 后续只按稳定 ID 联调。
4. `position`、`geometry.size` 使用米，`velocity` 使用米/秒，`timestamp` 使用整数毫秒；第一阶段 `clock_domain` 固定为 `unix_utc`。
5. 第一阶段 `coordinate_system` 固定为 `robot_base`。如果 A 只能输出相机坐标，必须先提供外参和坐标转换方案，不能只改字符串。
6. 四元数顺序固定为 `{x, y, z, w}`，应归一化；候选 `score` 使用 0～1，C 按最高分选择主类别/颜色/形状/纹理。
7. `category_candidates` 至少包含一个候选。外观候选允许为空数组，但不得用空字符串伪造结果。
8. 当没有检测到对象时，发送 `objects: []`，仍须提供本次新的 `observation_id`；不要重复发送旧场景冒充新结果。

## 3. `simulation_metadata` 的边界

- `simulation_metadata` 只用于仿真评测和结果对照，必须标记 `evaluation_only: true`。
- A 不得把 ground truth 的 `material`、`mass_kg`、`friction` 等偷偷复制到普通感知候选中。
- C 不使用该字段判断真实运行中的类别、可抓取性或安全性。
- 可抓取性、碰撞、工作空间和目标区域安全性由 C 的 Mock/Isaac/real backend 根据本地能力判断。

## 4. 需要 A 负责人立即确认的 6 项

- [ ] 是否能保证每条消息都是完整场景快照。
- [ ] `object_id` 的稳定周期是单帧、单场景还是整个运行会话；要求至少覆盖单场景任务全过程。
- [ ] 放置区域能否作为普通 `objects[]` 对象输出，并拥有稳定 `object_id`。
- [ ] 实际输出单位是否确认为米、米/秒和 Unix UTC 毫秒。
- [ ] 实际四元数是否为 `xyzw` 且已归一化。
- [ ] `simulation_metadata` 在非仿真输入中是完全省略，还是发送空的 ground truth 数组。

## 5. A 的失败处理

以下情况不能继续输出可执行 `READY` 任务，应由 A 阻断或请求澄清：

- 目标或目的地没有稳定 ID；
- 多个候选均可执行，场景仍不能唯一消歧；
- 坐标系、单位或时间来源不明确；
- 同一消息出现重复 `object_id`；
- 目标置信度不足且错误执行存在风险。

## 6. 联调验收

A 将至少提供三条冻结样例：正常单目标、多候选但可唯一消歧、必须澄清/阻断。C 运行：

```powershell
conda run -n huawei python -m pytest tests/contract/test_perception_observation_schema.py tests/unit/test_perception_observation_normalizer.py -q
```

验收条件：原始消息通过契约；C 转换后的对象 ID、主类别、位姿、尺寸、候选列表和来源元数据均与 A 输入一致；C 不从评测真值推导运行决策。
