# 具身智能系统统一联调仓库使用手册

## 1. 这个仓库解决什么问题

本仓库是最终集成仓库，不要求大家重写自己的模块。每个模块保留自己的实现，只需通过适配器接入统一协议，便可以在同一条链路上运行和验收。

## 2. 模块对应关系

| 模块 | 目录 | 输入 | 输出 |
|---|---|---|---|
| 感知 | `modules/perception` | 相机/Isaac Sim 场景 | `perception.v1` |
| 意图理解 A | `modules/intent_understanding` | 语言+感知 JSON | `task.v1` |
| CodeArts 策略 B | `modules/strategy_generation` | `task.v1` | `strategy.v1` |
| Isaac Sim/真机 C | `modules/executor` | `strategy.v1` | `execution.v1` |
| TraceCoder/TraceProbe D | `modules/evaluator` | 执行轨迹 | `feedback.v1` |

## 3. 每个目录放什么

- `contracts/`：唯一接口标准和 JSON Schema。
- `modules/`：各模块源码或作为外部仓库的接入副本。
- `integration/`：跨模块编排、适配器和环境配置。
- `tests/unit/`：单模块测试。
- `tests/contract/`：输入输出 Schema 测试。
- `tests/integration/`：两个或多个模块的联调测试。
- `tests/e2e/`：自然语言到执行结果的完整闭环测试。
- `testdata/`：日常、工业、故障注入和回归样例。
- `docs/`：架构、接口、部署和故障排查说明。
- `logs/`：本地运行日志；正式提交只保留脱敏样例。

## 4. 怎么接入自己的模块

1. 在 `modules/<模块名>/` 放代码，或保留外部仓库并在此处建立适配器。
2. 在 `integration/adapters/` 实现 `run()` 和 `health()`。
3. 读写对应的 `contracts/v1` JSON，不直接调用其他模块的内部函数。
4. 增加至少一个正常样例和一个失败/阻断样例。
5. 本地通过单测、契约测试后提交 Pull Request。

## 5. 联调顺序

先用 Mock 数据打通：感知 → 意图 → 策略 → 执行 → 反馈；再接 Isaac Sim；最后接真机。每一步都保存输入、输出、版本号和时间戳，出现问题时按 `task_id` 串起完整链路。

## 6. 提交规则

- 分支：`feature/<模块名>-<功能>`。
- 接口变更必须更新 Schema、示例和契约测试。
- 不提交 API 密钥、真机地址和大体积运行日志。
- PR 必须说明：改了什么、影响哪个协议、测试结果是什么。

## 7. 后续联调目标

第一阶段：所有模块完成 `v1` 协议适配，Mock 闭环跑通。

第二阶段：接入 Isaac Sim，验证策略执行、轨迹记录和 TraceCoder 修复闭环。

第三阶段：接入真机，增加急停、权限、超时和人工确认门禁。

最终验收以端到端结果为准：输入指令可追踪、目标 ID 不丢失、危险任务能阻断、策略可执行、执行结果可回传，且同一测试集可以重复复现。
