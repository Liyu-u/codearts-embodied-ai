# 前端接口与仿真平台接入说明

本文说明当前前端、Demo 后端和 A/B/C/D 闭环之间的连接关系，供后续接入 Isaac Sim、真实 RGB-D 摄像头和真机时使用。

## 1. 当前代码边界

- 前端文件：`demo/frontend/index.html`、`demo/frontend/app.js`、`demo/frontend/styles.css`。
- 本地服务：`demo/server.py`，使用 Python 标准库提供静态文件和 JSON 接口。
- 前端只调用 `/api/*`，不直接调用 A、B、C、D 的 Python 内部函数，也不直接连接 Isaac Sim。
- 当前 Demo 的 `/api/run` 使用真实适配器和 C 的 `MockBackend`，服务返回中的 `server_mode` 会明确写成 `real-adapters-with-mock-executor`。这可以展示接口和闭环消息，但不能替代 Isaac Sim 或真机验收。
- `.model_config.local.json` 是本机持久化配置，已被 Git 忽略；接口只返回脱敏后的 Key 状态。

## 2. 启动方法

在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt
.\demo\start_demo.ps1
```

浏览器访问 `http://127.0.0.1:8765/`。如果使用虚拟环境，把 `python` 换成虚拟环境中的解释器，或传入：

```powershell
.\demo\start_demo.ps1 -PythonPath .\.venv\Scripts\python.exe -Port 8766
```

只使用本地规则和 Mock：

```powershell
.\tools\setup.ps1 -IntentMode rule -TraceCoderMode off -CodeArtsMode off
```

正式真实智能模式：

```powershell
.\tools\setup.ps1 -IntentMode llm -TraceCoderMode required -CodeArtsMode required
.\demo\start_demo.ps1 -CodeArtsMode required -CodeArtsPolicy quality
```

真实 Key 只能写入本地 `.env`、`tracecoder_llm.env` 和 `codearts.env`，不能写入前端、源码、报告或 Git 提交。

## 3. 前端接口清单

所有接口默认使用当前页面所在域名，基础路径为 `/api`。成功返回 JSON；失败通常返回 `{"ok": false, "error": "..."}`。

### 3.2 写入和执行接口

| 方法 | 路径 | 请求重点 | 当前状态 |
|---|---|---|---|
| POST | `/api/run` | `{scene_id, instruction, engine?, request_id?}` | 已连接 A→B→C→D；C 当前为 Mock |
| POST | `/api/tasks` | `{name, instruction, scene_id?}` | 返回演示任务；尚未接任务数据库 |
| POST | `/api/robots/{id}/commands` | `{command: "PAUSE\|STOP\|ESTOP", ...}` | 返回已接收；尚未驱动真机 |
| POST | `/api/scenes` | `{id?, name?, ...}` | 返回草稿场景；尚未写入场景库 |
| PUT | `/api/settings` | 设置对象 | 当前只在本次服务进程内生效 |
| PUT | `/api/model-config` | `{modules: {A,B,C,D}}` | 写入 `.model_config.local.json` 并刷新本进程配置 |
| PUT | `/api/scenes/{id}` | 场景更新内容 | 当前返回版本号占位，尚未持久化 |

### 3.3 `/api/run` 的闭环约定

请求示例：

```json
{
  "scene_id": "stacking_cubes",
  "instruction": "把绿色方块放到桌子上",
  "engine": "llm",
  "request_id": "ui-demo-001"
}
```

返回结果至少包含：

- `request_id`、`elapsed_ms`：本次请求追踪信息；
- `scene`：送入感知边界的场景；
- `result`：A/B/C/D 闭环结果，包含最终状态、任务编号、策略、执行和反馈信息；
- `backend_snapshot`：Demo 执行器快照；
- `acceptance`：场景预期状态与实际状态是否一致；
- `metrics`：本次运行的统计结果；
- `server_mode`：当前是否仍为 Mock C。

前端只根据返回状态展示结果，不自行推断成功。真实后端接入后必须继续保留 `task_id`、`object_id`、`destination_id`、`request_id` 和来源信息。

## 4. A/B/C/D 配置对应关系

| 模块 | 本地配置 | 作用 | 接入仿真时的要求 |
|---|---|---|---|
| A | `.env` | 把语言和感知场景整理成 `task.v1` | 不得把模型返回的对象编号直接当成仿真对象，必须经过场景绑定和约束检查 |
| B | `codearts.env` | 把 `task.v1` 变成安全的 `strategy.v1` | CodeArts 失败、空策略、错误编号都必须阻断，不能让 C 猜测执行 |
| C | `EXECUTOR_BACKEND` 和执行配置 | 消费 `strategy.v1`，输出 `execution.v1` | Mock、Isaac Sim、真机必须实现同一后端接口；真实接入前先做单步动作和急停测试 |
| D | `tracecoder_llm.env` | 根据 `execution.v1` 生成 `feedback.v1` 和有限修复 | 修复只能返回经过校验的补丁，不能改变原目标或绕过动作白名单 |

推荐配置顺序：`rule + mock` → `hybrid/llm + mock` → `llm + CodeArts + Mock C` → `llm + CodeArts + Isaac Sim` → 真机。

## 5. 接入 Isaac Sim 的步骤

### 5.1 不改前端接口

Isaac Sim 接入应放在后端适配器层：

1. 相机或 Ground Truth 输出 `perception.v1`；
2. A 读取 `perception.v1` 生成 `task.v1`；
3. B 读取 `task.v1` 生成并校验 `strategy.v1`；
4. C 的 `IsaacSimBackend` 执行策略并返回 `execution.v1`；
5. D 读取执行轨迹并返回 `feedback.v1`；
6. `/api/run` 继续使用同一返回结构，前端无需知道 C 是 Mock 还是 Isaac Sim。

### 5.2 C 后端替换要求

- 使用 `integration.config.loader.build_backend()` 或现有 `ExecutorAdapter` 接入，不在 `demo/frontend` 中写 Isaac 逻辑。
- `EXECUTOR_BACKEND=isaac` 时，必须明确返回 `provenance.backend=isaac` 或等价真实来源标记。
- 物体移动前后要从 Isaac Sim 场景回读位姿，不能只根据本地变量宣布成功。
- 传感器、场景、机器人和目标对象使用稳定 ID；同一 `task_id` 的输入、策略、轨迹和反馈必须能串起来。
- 碰撞、超时、工作空间越界、通信中断、急停都要 fail-closed：停止动作并返回明确状态。
- 真实 RGB-D 摄像头接入时，保留 `camera_id`、帧号、时间戳、深度质量、坐标系和检测来源；不能用 Ground Truth 字段冒充相机检测。

### 5.3 前端需要补充的实时能力

当前页面展示的是一次请求结果，下面接口仍是预留：

- `WS /api/events`：任务状态、执行步骤、反馈和安全事件的实时推送；
- WebRTC/RTSP：仿真画面或相机视频；
- `GET /api/robots/{id}/telemetry`：真实关节和安全遥测；
- 场景版本和轨迹下载接口。

建议先实现事件通道，再接视频。事件消息统一携带 `event_id`、`task_id`、`run_id`、`timestamp`、`stage`、`status` 和 `provenance`，前端按 `event_id` 去重，不能靠页面刷新猜测任务状态。

## 6. 后续开发必须遵守的事项

1. **契约先行。** A/B/C/D 之间只通过 `contracts/v1` 的 JSON 交换；改字段时同时更新 Schema、适配器、样例和测试。
2. **前端不做安全判断。** 允许执行、目标绑定、碰撞和急停只能由后端决定，前端只展示后端结论。
3. **真实来源要写清楚。** 页面和报告必须区分 Mock、规则、DeepSeek、CodeArts、Isaac Sim 和真机，禁止把 Mock 成功显示成真实仿真成功。
4. **禁止把密钥发到浏览器。** 生产环境不应允许浏览器直接提交 A/B/D 的原始 Key；应由后端安全配置中心或进程环境管理，并增加登录、权限、审计和 CSRF 防护。
5. **所有写接口要有权限。** 当前 Demo 没有登录鉴权，`/api/model-config`、机器人命令和场景写入不能直接暴露到校园网或公网。
6. **硬件动作必须有人工门禁。** 真机的 `STOP`、`ESTOP`、速度、力限制和工作空间校验不能由前端按钮绕过。
7. **失败不能静默降级。** 在线验收时 Provider 失败、空策略、未知目标、错误 ID、补丁不合法都要明确阻断并保存原因。
8. **先 Mock、再仿真、最后真机。** 每一步使用同一测试集和同一接口，比较状态、来源、延迟、错误、修复和安全停止结果。
9. **日志可追溯。** 运行记录至少保存 `request_id`、`run_id`、`task_id`、模块来源、模型/Agent、场景版本、策略摘要、执行轨迹和反馈结论；密钥、Cookie 和完整 Authorization 不得写入日志。
10. **当前验收结论要如实标注。** 完整智能测试最近结果为 29/30，尚未达到 30/30；前端提交不等于系统已经通过真实摄像头、Isaac Sim 或真机上线验收。
